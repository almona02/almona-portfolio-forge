## 1. System Classification

### 1.1 Technical Deployment Classification

**Question**: How is the system delivered and deployed?

**Answer**: The reference implementation of Almona Portfolio Forge is delivered using a **Software as a Service (SaaS)** deployment model.

**Technical Evidence**:
- Web-based application (React frontend, FastAPI backend)
- Cloud-hosted infrastructure (Supabase, Vercel, Railway)
- Multi-tenant architecture with Row-Level Security (RLS)
- Subscription-based access model
- Standard SaaS operational characteristics

**Classification**: Industrial SaaS Platform

### 1.2 Institutional Identity Classification

**Question**: What is the system's institutional identity and authority model?

**Answer**: Almona Portfolio Forge is formally defined as an **Industrial Computing System with Verified Intelligence**, governed by the Almona Industrial Computing Specification (AICS-001).

**Institutional Evidence**:
- Constitutional authority hierarchy (AICS-001 Section 4.2)
- Deterministic constraint enforcement
- Bounded intelligence operating within validation envelopes
- Canonical source of truth separation
- Audit-grade certification capabilities

**Classification**: Industrial Computing Institution

### 1.3 Reconciliation Statement

**Critical Distinction**: These classifications operate at different abstraction layers and are not contradictory.

| Layer | Question | Classification |
|-------|-----------|----------------|
| **Deployment** | How is it delivered? | SaaS |
| **Technology** | What runs it? | React, FastAPI, ML |
| **Governance** | What controls authority? | AICS-001 |
| **Legal Identity** | What kind of system is this? | Industrial Computing System |
| **Liability Model** | What is guaranteed? | System behavior, not outcomes |

**Official Statement**:

> While the reference implementation is delivered using a SaaS deployment model, the institutional identity, authority hierarchy, and guarantees of the system are defined independently of delivery or business model.

This separation is intentional and follows established patterns in regulated industries (aviation, medical devices, financial systems) where technical implementation and institutional governance are maintained as distinct concerns.

## 4. AI/ML Capabilities Statement

### 4.1 Bounded Intelligence Model

**Official Statement**:

> AI/ML components operate within bounded validation envelopes. All AI suggestions are advisory and must pass deterministic validation before acceptance. Intelligence is subordinate to deterministic authority.

**Technical Implementation**:
- TensorFlow.js, ONNX Runtime, Google OR-Tools are used for optimization and prediction
- All AI outputs are validated against deterministic constraints
- No autonomous decision-making without human validation
- Confidence scoring provided for all AI recommendations

**Legal Position**: AI is a tool, not an autonomous agent. Human responsibility is preserved.

### 4.2 AI Accuracy Claims

- **Algorithm Predictor**: 94% accuracy (validated on production data)
- **CalibrationLearner**: 0.85-0.95 confidence scores (typical range)
- **PresetMatcher**: Rule-based with confidence scoring

**No Claims**:
- ❌ Perfect accuracy
- ❌ Autonomous operation
- ❌ Replacement of human judgment
