## 2. Critical Gaps to Reach Gold-Tier Parity

These are **expectation gaps**, not architectural risks.

### 🔴 A. Tender / Quotation Engine (CRITICAL - #1 Commercial Gap)

**Gold-Tier Expectation:**
- Multi-option quotation (System A vs B vs C)
- Variant comparison with cost breakdown
- Margin rules and discount logic
- Customer-ready tender PDFs
- Integration with BOM truth

**Why This Matters:**
> Orgadata & Klaes win sales rooms, not workshops. The quotation engine is how technical offices evaluate software before workshops ever see it.

**ALMONA Needs:**
- **Quotation Compiler** (Tier 1 + Tier 3 hybrid)
  - Tier 1: System pack suggestions, material intelligence
  - Tier 3: Deterministic pricing structure enforcement
- **Strong BOM Integration:** Quotations must reflect actual manufacturable outputs
- **Multi-Variant Comparison:** "Option A (Caluminium PS) vs Option B (ASAS CW100)" with cost/performance trade-offs
- **PDF Export:** Professional tender documents with constitutional disclaimers

**Constitutional Constraint:**
- ❌ No pricing decisions (that's business judgment)
- ✅ Pricing structure enforcement (rules-based, deterministic)
- ✅ Cost calculation from BOM truth (not estimates)

**Priority:** **WEEK 17-20** (Phase 2, immediately after anchor client validation)

---

### 🔴 B. Library Depth & Trust Density (CRITICAL - Trust Accumulation)

**Gold-Tier Expectation:**
- Thousands of pre-certified system packs
- Accessories, gaskets, screws, seals, tolerances
- Years of accumulated "this works" knowledge
- Versioning: "System X v3.2 – Locked"
- Explicit status: "Approved / Deprecated / Experimental"

**Why This Matters:**
> Orgadata/Klaes advantage is **time**, not intelligence. They have decades of accumulated trust. ALMONA needs institutional certification, not just feature parity.

**ALMONA Needs:**
- **Fewer systems, but institutionally certified**
  - Quality over quantity
  - Each system pack has:
    - Certification authority (supplier, testing lab, etc.)
    - Version lock (immutable after certification)
    - Status flags (Approved/Deprecated/Experimental)
- **Accessory Library Governance:**
  - Gaskets, screws, seals mapped to system packs
  - Tolerance rules encoded (not calculated)
  - Hardware compatibility matrix
- **Trust Artifacts:**
  - "Certified by [Supplier Name]"
  - "Used in [X] projects since [Date]"
  - "Tested against [Standard]"

**Constitutional Constraint:**
- ❌ No "AI-generated" system packs
- ✅ All system packs must have explicit certification authority
- ✅ Versioning is immutable (constitutional truth)

**Priority:** **WEEK 5-16** (Phase 1, build certification infrastructure alongside curtain wall engine)

### 🟠 C. Installer / Site Reality Layer (MEDIUM - Production Extension)

**Gold-Tier Expectation:**
- Installation diagrams
- Assembly sequences
- Error-prevention logic for site teams
- QR-linked assembly views
- Site-specific cut & pack grouping

**Why This Matters:**
> Workshops need to know "how this goes together" not just "what to cut." This is where RealityOS can shine, but some basics are expected.

**ALMONA Needs:**
- **Assembly Sequencing Artifacts:**
  - Step-by-step assembly instructions
  - Installation order (what goes first, what depends on what)
  - Tool requirements per step
- **Installation-Specific Grouping:**
  - Cut lists grouped by installation location
  - Pack lists organized by site sequence
  - QR codes linking physical parts to digital instructions
- **Error-Prevention Logic:**
  - "This panel requires [X] before [Y]"
  - "Missing hardware: [list]"
  - "Tolerance check: [measurement] must be within [range]"

**Constitutional Constraint:**
- ❌ No installation "recommendations" (that's engineering judgment)
- ✅ Installation sequences from system pack definitions (deterministic)
- ✅ Error detection (not prevention—that implies authority)

**Priority:** **WEEK 25-28** (Phase 2, after basic complex glazing)

## 2.5. Subtle Execution Multipliers (Expectation Enablers)

These are **not features**—they are **expectation enablers** that gold-tier buyers subconsciously expect. They are subtle but critical for adoption.

### 🔴 F. Sales-Side Cost Intelligence Layer (VERY IMPORTANT - Not Obvious)

**Gold-Tier Expectation:**
- Cost drivers explanation ("Why Option A is more expensive than B")
- Sensitivity knobs (glass thickness, system depth, hardware grade)
- Deterministic cost breakdown narratives

**Why This Matters:**
> This wins technical offices, not workshops. Gold-tier tools implicitly provide cost intelligence that helps technical offices explain pricing to clients.

**ALMONA Needs:**
- **Cost Breakdown Narrative Generator:**
  - Not AI "recommendation" (constitutionally prohibited)
  - Deterministic explanation from BOM deltas
  - Output: "Option B costs +7.4% because mullion depth increased from 120mm → 150mm and hardware set changed."
- **Sensitivity Analysis:**
  - "If glass thickness changes from 6mm → 8mm, cost increases by X%"
  - "If system depth changes from 100mm → 120mm, cost increases by Y%"
  - All calculations from BOM truth, not estimates

**Constitutional Constraint:**
- ❌ No pricing "recommendations" (that's business judgment)
- ✅ Cost explanation from BOM deltas (deterministic, factual)
- ✅ Sensitivity analysis from system pack rules (not AI inference)

**Where It Fits:**
**Phase 2 (Week 17-20), inside Quotation Engine, not a new module.**

**Files to Create:**

### 🔴 G. Migration Safety Net from Orgadata/Klaes (CRITICAL for Adoption)

**Gold-Tier Expectation:**
- Read-only import / reference viewer for legacy projects
- Historical BOM comparison
- Legacy project "lock & archive" functionality

**Why This Matters:**
> Gold-tier buyers fear: "We already have 10 years of Orgadata projects. What happens to them?" You don't need full migration—but you need a safety net that reduces switching anxiety.

**ALMONA Needs:**
- **Legacy Project Reference Mode:**
  - Read-only import from Orgadata/Klaes formats
  - No recalculation
  - No re-optimization
  - Pure read + compare
  - Historical BOM comparison (side-by-side view)
  - Legacy project "lock & archive" (immutable reference)

**Constitutional Constraint:**
- ❌ No automatic migration (that implies authority over legacy data)
- ✅ Read-only reference (no modification of legacy projects)
- ✅ Comparison only (factual, not judgmental)

**Where It Fits:**
**Phase 1.5 (between Week 13-16), very small scope, huge trust gain.**

**Files to Create:**

**Constitutional Constraint:**
- ❌ No automatic overrides (that's AI judgment)
- ✅ Explicit human responsibility (visible, auditable)
- ✅ Override reasons required (accountability)

**Where It Fits:**
**Phase 3 (Governance & Audit, Week 37-40), but UI hint can appear earlier (Week 17-20).**
